pcilmr:單機快篩、內建分級與硬體特例表

pcilmr 是 pciutils 套件內附的 Lane Margining 工具(lspci 的同家族),最大特色是內建結果分級與硬體特例(quirk)資料庫,讓你不必自己寫判定邏輯就能得到初步結論;也因為它在標準發行版裡,常是現場最快的選擇。[4]

是什麼、從哪來

  • 來自 pciutils(lspci 的家),因此幾乎所有 Linux 發行版都有或可一行安裝[4]
  • 取得 16.0 GT/s 以上埠(含 retimer 的 pseudo port)的電壓與時間 margin 資訊;時序量測必要、電壓 16 GT/s 選配、32 GT/s 以上必要[4]
  • 可取得「四點菱形」形式的眼圖 margin 近似[4]
  • 不需硬體除錯器、不需停止目標系統;需 root 以存取擴充 config space[4]
  • 實測後裝置都能正常回到原本狀態[4]
  • 設計初衷即為除錯因接收端 margin 造成的鏈路問題[4]

目前已支援 16 GT/s 與 32 GT/s 鏈路(工具的支援範圍以你的 pciutils 版本為準)。[4]

三種模式

模式作用用途來源
--scan掃描速率 ≥16 GT/s 的鏈路,並標記「Ready」——即至少一側的 Margining Ready 位元已設量測前先確認哪些 link 可以量[4]
--margin <downstream components>對指定鏈路執行 margining日常量測[4]
--full對系統中所有「Ready」的鏈路逐一 margining全機掃描、一次性盤點[4]

命令列選項全表

選項說明預設來源
-c只印出裝置的 Lane Margining 能力,不執行 margining—[4]
-e <errors>錯誤計數上限4[4]
-o <directory>把結果以 CSV 存到指定目錄,檔名格式 lmr_<port>_Rx#_<timestamp>.csv—[4]
-d <time>每個 margining 步的 dwell 秒數1 秒[4]
-l <lane...>指定 lane(邏輯編號);工具會自動偵測 lane reversal 並調整呼叫全部 lane[4]
-r <recvn...>指定接收器編號所有可用接收器(含 retimer)[4]
-p <n>同時 margin 的 lane 數(依規格可達 MaxLanes+1)1(實驗性質,見下)[4]
-T / -t <steps>時間 margining:跑到錯誤超過上限,或指定最大步數用裝置能力上限[4]
-V / -v <steps>電壓 margining:同上用裝置能力上限[4]
-g <recvn> t= / v=指定該接收器的眼寬(時間)或眼高(電壓)合格標準內建參考值[4]
注意 · -T/-t 與 -V/-v 不可同時使用同一組

手冊明確提醒:同一時間只能用 -T/-t 其中之一(電壓同理);若不指定,工具會以裝置能力回報的 MaxSteps 作為量測上限。-T / -V 的語意是「持續跑到錯誤超過上限」,適合用來找出鏈路極限。

[4]

BIOSError Threshold 設為 0—[4]

★ 建議 · ★ 這一節是四份文件裡對「量測前平台設定」最具體的清單

Intel 指南列出的是前置條件(ASPM、自主升降速/寬),而 pcilmr 額外點出 Xeon 平台的 leaky bucket / re-equalization / link degradation 與 error threshold 設定。[4][5] 建議把這張表直接做成量測前 checklist。

內建分級參考值

pcilmr 會用 PCIe Base Spec Rev 5.0 §8.4.2 的眼寬/眼高最小值作為預設參考,並取 PCIe Architecture PHY Test Spec Rev 5.0(發射端電氣合規)的建議值作為 Recommended 水準。[4]

項目16 GT/s(Gen4)32 GT/s(Gen5)來源
眼寬 Min30% UI / 18.75 ps30% UI / 9.375 ps[4]
眼寬 Recommended38% UI / 23.75 ps33% UI / 10.157 ps[4]
眼高 Min15 mV15 mV[4]
眼高 Recommended21 mV19.75 mV[4]

評分選項 -g 與單邊問題

並非所有裝置都支援雙向(獨立左右/上下)margining;遇到只支援單邊的裝置時,工具預設會把單邊結果乘以 2 當作完整眼寬/眼高。[4]

  • -g <recvn> t=<criteria>{%,ps}:設定眼寬門檻(%UI 或 ps)[4]
  • -g <recvn> v=<criteria>:設定眼高門檻(mV)[4]
  • -g <recvn> t=f,<criteria>:加上 f 旗標代表「單邊結果本身就是完整眼」,不要再乘 2(one side is the whole 模式)[4]
  • 若已知特定裝置的行為,可用 -g 替該裝置調整評分方式[4]
pcilmr -o csv ab:0.0 -r 1,6 -g 1t=20% -g 1v=f,30 52:0.0 -l 0,1,2 -TV

硬體特例(HW quirks)

工具內建一份以 Vendor ID – Device ID 比對的特例清單(在 margin_hw 檔中):遇到清單中的裝置會自動調整 margining 參數或評分方式。[4]

  • 例(Ice Lake CPU 的 RC 埠):pcilmr 會修改裝置的 MaxVoltageOffset 值,並強制使用「單邊即完整」的評分模式[4]
  • ★ 實務建議:對自家常見的 CPU / retimer / switch 型號,主動把 quirk 清單當成「已知行為差異」的索引表;若你的平台不在清單中但行為怪異,可回報社群或自行以 -g 調整[4]
★ 建議 · 這份 quirk 清單的價值

它記錄了「廠商實作與規格解讀不一致」的真實案例。對品牌商而言,這正是收集自家平台特殊行為的範本:哪個型號必須單邊、哪個型號回報值要修正、哪個型號要避開特定設定。

[4]

並行量測的警告

重要 · 原文警告

「依規格,接收器可同時 margin 最多 MaxLanes + 1 條 lane,但測試期間同時量多條 lane 得到的結果與循序量測不同,因此此功能仍需額外驗證,-p 目前主要供實驗用。」[4]

★ 這與 Google 版「lane-parallel 加速」的設計形成對比:[1] 若你的量產流程要用並行,務必自行驗證在你的平台/裝置組合上的一致性。
