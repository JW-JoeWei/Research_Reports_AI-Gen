Google pcie_lmt:Go 引擎、三種用法、量產導向

由 Google 釋出、Apache 2.0 授權的 Lane Margin Test 工具。它的設計目標很明確:用最少的人工介入,在量產環境對大量鏈路做可重複的 pass/fail 判定與眼圖掃描。[1]

測試規格(lmt.proto)欄位

同一份 proto 同時定義輸入規格與輸出結果;頂層指定要測的 link,每個「接收器點」(USP、DSP、retimer)各自有 timing 與/或 voltage 規格。[1]

欄位型別意義來源
vendor_id / device_iduint32(選填)以 ID 選 USP(例如端點裝置)[1]
bdf[]string(可重複)以 0000:00:00.0 選 USP;假設 domain=0, device=0, function=0[1]
usp_bdf / dsp_bdfstring(輸出)實測鏈路上回報的上下游埠 BDF[1]
receiverenumR_DSP_A1(1)、R_RTU_B2(2)、R_RTD_C3(3)、R_RTU_D4(4)、R_RTD_E5(5)、R_USP_F6(6)[1]
aspectenumM_TIMING / M_VOLTAGE[1]
samplesuint32取樣計數(0–127 = 3·log₂(位元數));取樣率模式時改以時間估算[1]
dwellfloat(選填)每個 margining 的最短秒數;實際取「估算時間」與 dwell 較大者[1]
error_limituint32允許錯誤上限 0–63[1]
start_offsetuint32(選填)從第幾步開始(眼圖探索用)[1]
stepuint32(選填)每次前進的步數[1]
target_offsetuint32(選填)目標偏移;只給它就變成快速 pass/fail[1]
eye_sizefloat(選填)要求的最小眼尺寸;若指定,target_offset 必須小於眼尺寸/2[1]
lane_number[]uint32(可重複)只測指定 lane(不填 = 該埠全部 lane);time/voltage spec 需一致[1]
lane_parametermessage(輸出)實測讀到的能力快照(步數、偏移、獨立位元、取樣器、最大 lane)[1]
timing_margins / voltage_marginsmessage(輸出)每個量測點:方向、步數、狀態、錯誤數、取樣數、%UI 或電壓[1]
pass / eye_width / eye_heightbool/float(輸出)該 lane 的判定與算出的眼寬眼高[1]

三種用法與實際 spec

proto 註解把用法分成三種,這也是它最實用的設計:[1]

用法必填行為典型場景來源
1. 眼圖探索start_offset(+step/target)從起點逐步往外,直到 ERROR_OUT 或到達 target_offset;eye_size 為次要條件新鏈路第一次量、不確定邊界在哪[1]
2. 目標偏移判定target_offset只檢查該偏移是否合格;忽略 start_offset、step、eye_size量產快速 pass/fail[1]
3. 眼尺寸檢查eye_size檢查偏心眼的最小尺寸;target_offset 需小於 eye_size/2抽驗眼開口是否足夠[1]

README 提供的兩個範例(可直接改成你的 spec)[1]

# 眼角掃描(電壓方向,retimer 下游接收器)
test_specs: {
  aspect: M_VOLTAGE
  receiver: R_RTD_C3
  samples: 110        # 3*log2(位元數) → 約 10^11 位元
  dwell: 10           # 秒
  error_limit: 10     # 最大 63
  start_offset: 4
  step: 1
  eye_size: 0.050
}

# pass/fail(時間方向,USP 側接收器)
test_specs: {
  aspect: M_TIMING
  receiver: R_USP_F6
  samples: 100        # 3*log2(位元數) → 約 1.0×10^10 位元
  dwell: 3
  error_limit: 1
  target_offset: 10   # 註解:31/50%*15%=10
}

# 實測讀回的裝置能力(節錄)
lane_parameter: {
  num_timing_steps: 31    max_timing_offset: 50    ind_left_right_timing: true
  voltage_supported: true num_voltage_steps: 127  max_voltage_offset: 49
  ind_up_down_voltage: true   ind_error_sampler: true   max_lanes: 15
}
解讀 · 讀懂範例裡的兩件事
  • units 與換算:結果會同時給步數、%UI 與伏特,換算公式見第 01 章百分比 = 最大偏移 × 步數 ÷ 總步數。[1]
  • exec status 會顯示在每個量測點上:S_MARGINING 代表「該點仍在 margining 中(合格)」、S_ERROR_OUT 代表錯誤過多、S_NAK 代表命令不支援。[1]

判定邏輯與邊界

Google 版的判定不是「工具幫你打分」,而是把規則寫進流程;理解這幾條才算真的會用:[1]

機制程式行為實務意義來源
合格偏移的定義某偏移點的狀態仍為 S_MARGINING 即視為通過,並記下最後一個通過點「通過」= 尚未超過錯誤上限,不是「零錯誤」[1]
兩側掃描scanEye 往正、負方向掃描,直到到達 target 或兩側皆不合格;眼寬/眼高 = 正側合格偏移 + 負側合格偏移eye_width/eye_height 是兩側相加的近似值[1]
eye_size 判定若 spec 指定 eye_size 且算出的尺寸小於它,則 ln.Pass = false,並在 OCP 輸出附上 GREATER_THAN_OR_EQUAL 驗證器這就是工具層級的 pass/fail 門檻,由你指定[1]
鏈路狀態檢查量測後重新讀取 Link Status,若寬度或速率改變則標記 linkcheck = false 並記錄訊息防止「鏈路中途降速/降寬」造成的假數據[1]
整體驗證lanemargintest 依每一 lane 的 Pass 彙整測試結果;有 lane 失敗即整體標記為失敗[1]
統計函式lmt_tally.go 提供 port/測試層級的 pass 統計,但註解明言預設不被使用要自己做報表統計[1]

輸出與串流

輸出內容給誰用來源
result.pbtxt每個 lane 的量測點(方向/步數/狀態/錯誤數/取樣數/%UI 或電壓)、能力快照、pass 與眼尺寸自動化後處理、資料庫[1]
result.html圖形化報告:Margining 模式與測試環境、全域訊息/鏈路記錄、LMR 量測表與非量測錯誤工程師閱讀、留檔[1]

OCP artifact(JSON/串流)符合 OCP 診斷規格的輸出,可用 named pipe 串到測試執行器MES / 測試管理系統[1][6]
