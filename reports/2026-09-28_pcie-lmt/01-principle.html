LMR:機制、訊號定義與規格邊界

Lane Margining at Receiver(LMR,工具端常稱 LMT)是 PCI-SIG 在 PCIe 4.0 加入的標準化接收端容限量測能力。本章講清楚它量什麼、量到什麼程度、以及規範在哪裡。

PCIe 4.0 起PCIe Base 5.0 §4.2.13 / §7.7.7 / §8.4.4強制能力L0 下量測

一句話定義與三個層次

LMR 讓系統軟體在鏈路持續運作(L0)的情況下,讀取指定接收器在時間與電壓兩個方向上的容限資訊,方法是把取樣點一步步推離眼圖中心、比對錯誤計數,直到超過設定的錯誤上限或步數用盡。[1][4]

層次內容誰在意
訊號層接收器的取樣位置可在時間軸(±UI)與電壓軸(±mV)上被程式化偏移;每次偏移後統計錯誤數PHY / SI 團隊
機制層命令與回應透過 Config Space 的 Lane Margining 擴充能力(Ext Cap ID 0x27)傳遞;命令之間需要 No Command 廣播與時序限制韌體 / 驅動 / 工具開發
應用層用同一套命令取得「這條鏈路還剩多少餘裕」,並可逐 lane 定位問題平台驗證 / 產線 / 維修

為什麼 PCI-SIG 要做這件事

PCIe 4.0 把速率推到 16 GT/s 後,通道損失、反射、串音與連接器不連續性對眼圖的影響被放大;同一塊背板上的不同插槽、不同料批甚至不同溫度,都會讓可用 margin 產生差異。[9]

這些差異在設計階段難以用模擬涵蓋,而在量產階段若沒有可重複的方法,就只能靠換零件猜問題。Lane Margining 的目的就是把「還剩多少餘裕」變成一個標準化、可在實際平台上量測的數字:[4][9]

  • 不需要額外測試設備(免示波器、免 BERT),在 production 平台就能做[2]
  • 可在跑 production traffic 的狀態下量測真實 margin,而不是實驗室特例[2]
  • 能指出是哪一對線/pin 有問題,以及相對標稱系統「有多壞」[2]
  • 避免因為反覆換零件造成的過度維修,並可在維修後驗證根因是否真的修好[2]

而 64 GT/s(PAM4)把難度再推高:奈奎頻率達 32 GHz、通道損失量級上看 70 dB,訊號完整性驗證的複雜度顯著上升,這也是 Gen6 把電壓量測改為強制的原因之一。[8][4]

量測模型:偏移掃描如何變成 margin

LMR 的核心動作只有一個:把接收器的取樣點往某個方向移動 N 步,然後數錯誤。往兩側各自掃描,記錄「最後一個仍合格的偏移」,兩側合格偏移相加就得到該 BER 條件下的眼寬/眼高近似值。[1][4]

量到什麼表示法計算方式(來源)
時間 margin(單側)% UI 與步數percent_ui = max_timing_offset(%) × steps ÷ num_timing_steps[1]
電壓 margin(單側)伏特與步數voltage = max_voltage_offset(%) × steps ÷ num_voltage_steps[1]
眼寬UI(兩側相加)合格偏移(正) + 合格偏移(負)(eye-scan 模式下)[1]
眼高V(兩側相加)同上,電壓方向[1]
錯誤率BER 或錯誤計數依裝置支援的回報方式:取樣計數或取樣率[5]
狀態4 種執行狀態錯誤溢位 / 設定中 / margining 進行中 / NAK[1][2]

LMR 與其他量測手段的關係

LMR 不是要取代示波器或 BERT,而是補上「系統內、可重複、可裝機後執行」這一格。同一份 PCIe 鏈路上,不同工具回答不同問題:[9][4]

手段回答什麼問題LMR 的差異點
示波器(時域眼圖)發射端訊號品質、抖動成分、週期性干擾LMR 量的是接收端實際判決眼開口,且不需停機[9]
BERT / 位元錯誤率量測特定條件下的 BER 與 bathtubLMR 不需外接設備,可在 production 系統上跑[2]
VNA / TDR通道插入損失、反射、不連續位置LMR 是「結果面」量測,不定位實體不連續點[9]
LMR / LMT這條鏈路在實際運行狀態下還剩多少時間/電壓餘裕,逐 lane三者互補:定位用 VNA/TDR,品質用示波器/BERT,量產與維修用 LMR

側菜:LTT 鏈路訓練測試

Google 的 repo 另外附帶 ltt(PCIe Link Training Test),確保鏈路能可靠地反覆建立:[1]

  • 把鏈路訓練重複指定次數,每次迭代之間檢查鏈路狀態[1]
  • 支援三種訓練方式:retrain(Link Retrain,預設)、sbr(Secondary Bus Reset)、reenable(Link disable/re-enable)[1]
  • 以 proto 指定要檢查/記錄的 config space 欄位(name / addr / size / mask / 期望值),並統計 pass/fail 次數[1]
  • 可獨立執行,也可整合進上層流程;預設平行測試多條 link[1]

實務上 LTT 與 LMT 是同一條鏈路的兩件事:先確保連得上(LTT),再量連得好不好(LMT)。[1]
