四份索取清單

★ 以下四份清單為本報告建議的協作框架;每一項的「為什麼」都連到規格或官方文件。

清單項目為什麼要
① 能力值書面確認Number of Timing/Voltage Steps、Max Timing/Voltage Offset(含單位)、Independent Left/Right、Independent Up/Down、Independent Error Sampler、Sample Reporting Method、Max Lanes、Voltage Supported這些由裝置廠商定義,工具與使用者都不得修改;實測值需與書面值核對[5]
② Margin mask(門檻)逐速率(16/32/64 GT/s)、逐接收器位置的合格眼寬/眼高(單位與 BER 條件)規格不定義數值門檻,廠商準則是唯一有來源的門檻[5]
③ 已知問題 / quirk實作差異、必須單邊量測、回報值需修正、不支援的命令與條件避免把命令不支援誤判為 margin 不足;pcilmr 的 quirk 表即為實例[4][1]
④ 韌體與工具建議的 FW/BIOS 版本、變更記錄、支援的工具版本FW/BIOS 換版可能改變量測結果,門檻需重新確認[5]
★ 溝通要點 · 能力值與門檻不要混為一談

文件明言:這些 margin device capabilities 由各裝置廠商定義,LMT 不會修改它們,使用者也不得修改。[5] 而數值門檻則被明示為「規格未定義、洽廠商」。[5] 所以在同一封索取信裡,建議把能力值與mask 門檻分成兩個段落要求,避免對方只回其中一種。

給廠商的問題範本

★ 以下範本為本報告撰寫,非引用自文件;可直接改寫使用。

主旨:PCIe Gen5 x16 Lane Margining 量測準則與能力值確認需求

說明:我方為 <產品/平台名稱> 系統品牌商,需在量產驗證 LMT 的可執行性與數值判定。
量測依 PCIe Base Spec 5.0 §4.2.13 / §7.7.7 / §8.4.4,工具使用 OCP pci_lmt v1.5.2。

（A）能力值書面確認:請提供 <型號> 於 16/32 GT/s 下的
     Number of Timing Steps / Max Timing Offset / Number of Voltage Steps /
     Max Voltage Offset / Ind Left-Right Timing / Ind Up-Down Voltage /
     Ind Error Sampler / Sample Reporting Method / Max Lanes / Voltage Supported
（B）Margin mask 準則:請提供逐速率的合格眼寬與眼高(單位 %UI / ps / mV)及對應 BER 條件,
     並說明該準則適用的 error count limit、取樣量(dwell 或 bits)與量測方向。
（C）已知行為:是否有必須單邊量測、回報值需修正、或命令不被支援的情形?
（D）lane reversal:埠是否支援?我方指定 lane 編號時的方向定義為何?
（E）版本關聯:上述準則對應的 FW / BIOS 版本,以及變更時是否需要重新確認?

我方將以 「（B）準則」作為對外驗收依據、「（A）+ 自家 golden 樣本」作為內部良率管理。

驗收與合約要點

要點內容備註
門檻入約把 margin mask 的具體數值與適用條件寫進規格書/驗收條款才有可執行的對外依據[5]
版本綁定條款綁定 BIOS / FW / 工具版本換版即需重新確認[5]
方法寫死寫明工具、參數(dwell / error limit / samples)、鏈路狀態(L0、ASPM off)條件不同結果不可比[2][5]
例外清單廠商需提供 quirk/例外清單,清單內情形不計入不良避免爭議[4]
資料交付格式要求逐 lane 原始資料(見下節欄位建議)爭議時才有事證[2][3]
抽樣計畫合格品質水準與抽樣數,依量產 profile(第 09 章)設定★ 本報告建議

步驟產出驗收標準出處/理由

資料欄位建議

★ 本報告建議:不管用哪個工具,資料庫至少要有以下欄位;括號內為 OCP 結果中可直接對應的欄位名。

分類欄位用途
識別run_id、timestamp、asset_id / 序號、hostname、model_name、annotation(群組)把同一次執行與同一台機器串起來[2]
環境BIOS 版本、FW 版本、工具名稱與版本、鏈路速率、寬度、溫度沒有環境欄位,跨批次比較不成立[5]
能力快照num_timing_steps、num_voltage_steps、max_timing_offset、max_voltage_offset、ind_error_sampler、sample_reporting_method、ind_left_right_timing、ind_up_down_voltage、max_lanes、voltage_supported判斷結果是否在裝置能力內;分辨「能力差異」與「品質差異」[2]
量測條件error_count_limit、dwell_time_secs、samples / sampling rate、方向、步數條件不同即不可比[2][1]
結果lane、receiver_number、margin_type、step、error_count、ber、sample_count / bits、error、error_msg錯誤首次非零的步數是最有價值的特徵[2]
判定pass 旗標、eye_size、使用的門檻與門檻來源(L2/L3)、linkcheck爭議時可回溯門檻依據[1][2]

常見卡關與解法

卡關原因解法
廠商回「規格沒定義門檻」規格確實沒定義,對方講的是事實[5]改問「你們內部驗證用的準則」(mask)與「建議的 error limit / samples」——這是實務上拿得到的
量測時間太長,產線不接受samples 或 dwell 過大、逐條量測[1][5]改用 profile A/B(第 09 章),並評估驗證過的並行量測[4]
同一台機器重複量差異大步數留空(停止點不同)、環境未固定、溫度變化[5]固定步數與環境;建立重複性驗收(R1)
讀不到 margin 能力lane 編號與接線反向[5]切換 lane reversal 選項或改用反轉後編號[5][4]
margining 產生資料流錯誤裝置的 Ind Error Sampler = 0[5]確認該裝置是否可用於產線;OCP 需 --force,屬刻意選擇而非預設[2]
工具行為與文件不符各實作對命令編碼/評分的理解不同[1][2][10]用第二個工具交叉驗證;把差異回報工具上游[4]
