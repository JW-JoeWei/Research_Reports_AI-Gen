PCI-SIG 的正式立場

★ 最重要的一條 · 原文(Intel 使用者指南 §4.3)

“For margin masks, the PCI-SIG Specification does not define a pass/fail criterion in terms of margin values.”

“Note: Refer to your vendor device for guidance/criteria on margin masks.”[5]

同一份指南也指出:PCI-SIG workshop 測試的方式是参照《PCI Express Architecture Link Layer and Transaction Layer Test Specification》的特定章節。[5]

章節測試編號名稱來源
3.19.1Test 75-10System Lane Margining Test at 16 GT/s[5]
3.19.2Test 75-11System Lane Margining Test at 32 GT/s[5]
3.19.3Test 75-12System Lane Margining Test at 64 GT/s[5]
3.19.4Test 75-20Add in Card Lane Margining Test at 16 GT/s[5]
3.19.5Test 75-21Add in Card Lane Margining Test at 32 GT/s[5]
3.19.6Test 75-22Add in Card Lane Margining Test at 64 GT/s[5]
★ 觀念 · 為什麼「合規通過」不等於「你的系統合格」

合規測試檢查的是能力與流程(系統/AIC 在 16/32/64 GT/s 能否執行 lane margining);而 margin 的數值判準被明示為規格未定義、需洽裝置廠商。[5] 因此你不能用「通過 PCI-SIG 認證」推論這條鏈路的 margin 足夠——這是兩件事。

開源工具各自的判定方式

工具判定的依據是否內建門檻來源
Google指定 eye_size 後比較算出的眼寬/眼高;未達則 Pass = false;並檢查量測後鏈路是否降速/降寬無預設值,門檻由你寫進 spec[1]
OCP結果提供 eye_size 與 pass 旗標;BER 存在每筆量測中,由使用者判讀無預設門檻[2]
Intel工具回報 margin 值與失因;pass/fail 由使用者依廠商準則判定無(手冊明言洽廠商)[5]
pcilmr內建 EW/EH 分級:以 Base Spec Rev 5.0 §8.4.2 最小值與 PHY Test Spec Rev 5.0 建議值為參考有,但明示為參考值並建議洽廠商[4]

★ 觀察:唯一內建數值門檻的 pcilmr,也同時在文件裡建議「向特定裝置的廠商索取參考值」。[4] 這反過來證實了同一件事:數值門檻是 vendor-specific 的。

建議的三層門檻架構

層級數值來源用途能否對外承諾
L1 規格下限PCIe Base Spec 的眼寬/眼高最小值(參考 pcilmr 內建值)[4]初步篩選:低於規格下限一律視為異常,直接 OQA 攔下不建議單獨作為出貨標準
L2 廠商 mask向 CPU / retimer / endpoint 廠商索取 margin mask 準則[5]正式判定:每種裝置型號各自的合格偏移與 BER 條件✅ 可作為驗收依據(有來源)
L3 內部 guardband自家 golden 樣本統計(同型號、同 BIOS/FW、同材料批次)[5][3]把 L2 再收緊,吸收製程/材料變異;用於良率趨勢管理✅ 可作為內控,但不對外承諾

三層的關係是:L3 ⊂ L2 ⊆ L1 的「嚴格度」排序,但三者來源不同——L1 來自規格、L2 來自廠商、L3 來自你自己的資料。用 L1 當出貨標準的問題是它與實際裝置行為脫鉤;用 L3 當唯一標準的問題是無法對外說明。建議L2 對外、L3 對內。

向廠商索取 margin mask

這是 pass/fail 能不能落地的關鍵文件。依 Intel 指南,準則來源就是裝置廠商[5]。以下清單為本報告整理的索取要點(★ 建議,非規格):

要索取什麼具體項目為什麼需要
合格準則每個速率(16/32/64 GT/s)與每個接收器位置(DSP/USP/retimer)的 margin maskmask 是唯一有來源的數值門檻[5]
門檻型式以 %UI 或 ps 表示的眼寬門檻、以 mV 表示的電眼高門檻,以及對應的 BER 條件不同工具用不同單位,需先統一[5][1]
量測條件建議的 error limit、取樣量(位元數)、dwell、量測方向門檻只在特定條件下有效[5][1]
能力值書面確認Number of Steps、Max Offset、Independent L/R、Ind U/D、Ind Error Sampler、Sample Reporting Method、Max Lanes用來核對工具實測值;能力由廠商定義且工具/使用者不得修改[5]
lane reversal 行為埠是否支援反轉、編號方向如何對應影響 lane 指定與結果歸屬[5]
已知限制 / quirk該型號已知的實作差異、必須單邊量測、回報值需修正的情形pcilmr 的 quirk 表就是這樣累積出來的[4]
不支援情況哪些條件下會回 NAK 或能力未定義避免把「命令不支援」誤判為「margin 不足」[1][2]
韌體關聯門檻對應的 FW/BIOS 版本,以及變更記錄FW 換版可能改變量測結果,門檻需重新確認[5]

驗收條款怎麼寫(參考框架)

★ 以下為本報告建議的結構,供與廠商談判時使用;非引用自任何文件。

1. 標的:PCIe Gen5 x16, DSP(RecNum=1)與 USP(RecNum=6)兩側
2. 量測方法:PCI-SIG LMR(PCIe Base Spec 5.0 §4.2.13/§7.7.7/§8.4.4),
   工具:OCP pci_lmt v1.5.2 或等效;error limit = ;
   取樣 = 100(samples)即 10^10 bits;dwell = 1s;鏈路全程 L0、ASPM 關閉
3. 合格準則: 之眼寬/眼高門檻(單位 %UI 與 mV)
4. 抽樣與判定:每台機器全 lane 量測;任一 lane 未達門檻即判不合格
5. 例外處理:廠商須提供 quirk 清單;清單內情形不計入不良
6. 資料交付:每台機器輸出逐 lane 結果(欄位依第 12 章建議)
7. 版本綁定:本條款綁定 BIOS _____ 與 FW _____;版本變更須重新確認門檻

驗證門檻本身是否可靠

門檻定完後,還要確認量測系統本身的再現性;否則門檻只是製造爭議。

R1重複性:同一台機器連續量 5 次,逐 lane 的錯誤發生步數變異應在 ±1 步內
R2再現性:換另一台同型號量同一張卡/同一條 cable,比較分布是否重疊
R3並行 vs 循序:小樣本比對,確認並行加速不改變結論[4]
R4工具交叉:同一條鏈路用兩個不同工具量(如 OCP 與 pcilmr),確認結論一致[1][4]
R5溫度量測:在冷機與熱機(穩定運轉後)各量一次,確認門檻有足夠餘裕
★ 建議 · 為什麼要做 R1–R5

LMR 的結果會受溫度、FW 版本、接線方向、量測參數影響(見第 09 章陷阱表)。先把量測系統的不確定度抓出來,才有辦法判斷「這台機器是異常,還是這批就是這樣」。[3][5]

常見誤判

誤判真相處置
「工具說 fail,所以硬體壞了」失敗可能是命令 NAK(偏移超出能力)或設定錯誤[1][2]先看狀態欄位:S_NAK / ErrorOut / SettingUp
「這台機器的 margin 比別台低 3 步,是壞的」可能是溫度、lane 位置或線材差異用同型號 golden 樣本分布比較,而非跨型號比[3]
「能力值越大品質越好」能力值由廠商宣告,只代表能掃多遠[5]改看錯誤發生的步數
「PCI-SIG 認證過了就沒問題」合規測的是能力與流程,門檻需洽廠商[5]索取 margin mask 並建立內部 guardband
「單邊量測的數值可以直接乘 2」只有裝置宣告為 one-side-is-whole 時才成立[4]確認 device capability 與 pcilmr 的 f 旗標
